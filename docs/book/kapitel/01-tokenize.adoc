[[Tokenize]]
== Tokenize

Das LLM kann wie schon gesagt nichts mit Text anfangen. Deshalb braucht es einen Mechanismus den Text in einzelne Tokens aufzuteilen und diese Tokens in Zahlen zu wandeln und damit mathematische Operationen ermöglichen.
Ein Tokenzizer zerstückelt einen Text in kleine Bausteine, sogennante Tokens. Ein Token kann ein ganzes Wort, Teile eines Wortes oder eine Sequenz von Zeichen inklusive Satzzeichen darstellen. Jedem dieser Token wird eine Token-Id zugeteilt.


=== Konzept

Die Klasse SimpleTokenizerV1.kt ist ein einfacher regelbasierter Tokenizer, der aus rawText ein Vocabular mit stabilen numerischen IDs aufbaut.
Er erkennt Wörter mit Apostroph, typografischem Apostroph, Bindestrich und Unterstrich, einfache Satzzeichen sowie die Special Tokens "<|unk|>" und "<|endoftext|>".

Die Methode *encode* zerlegt neuen Text mit derselben Regex und mappt unbekannte Tokens auf die ID von UNKNOWN, statt sie zu verwerfen oder einen Fehler zu werfen.

Die Methode *decode* übersetzt IDs zurück in Tokens und setzt sie mit einfachen Leerzeichen- und Anführungszeichen-Regeln wieder zu Text zusammen.
Zusätzlich hält die Klasse ein Reverse-Mapping idToToken, stellt vocabSize bereit und ergänzt UNKNOWN sowie ENDOFTEXT immer am Ende des Vokabulars.

Nach allen normalen Tokens fügt buildTokenToId immer zusätzlich UNKNOWN (<|unk|>) und ENDOFTEXT (<|endoftext|>) mit eigenen IDs an.
encode nutzt dieses Vokabular für Token→ID (unbekanntes Token fällt auf UNKNOWN zurück), und decode nutzt die inverse Map idToToken für ID→Token.

Die Variable idToToken

----
wird über alle Einträge der `vocab`-Map erstellt.
Dabei wird jedes Paar von `token -> id` in ein neues Paar `id -> token` umgedreht.
`associate` baut aus diesen umgedrehten Paaren eine neue Map und weist sie `idToToken` zu.
So kann die `decode`-Methode später eine Token-ID schnell wieder in den zugehörigen Token-Text zurückübersetzen.

Somit sind wir nun in der Lage einen Text in Tokens bzw. Token-IDs aufzusplitten. Wir können nun einer Function *encode(text: String)* übergeben und dieser wird anhand des Vokabular in Token-IDs umgewandelt. Ist ein Token aus dem Text dem Vokabular unbekannt, so wird anstelle das Enum UNKNOWN (`const val UNKNOWN = "<|unk|>"`) zurückgegeben.

----

So wird aus einem rawText "Darling, do you like water?" ein Vocabular aus Tokens und Token-IDs erstellt, welches dann über den text "Hello, do you like tea?" encoded wird.
Wie man unschwer erkennen kann unterscheidet sich der Text vom Vocabular in den 2 Wörtern Darling -> Hello, water -> tea.

Das Vocabular wurde über die obengenannte Regex in folgende 7 folgende Tokens aufgesplittet:

1. Darling
2. ,
3. do
4. you
5. like
6. tea
7. ?

[source, kotlin]
----
val rawText = "Darling, do you like water?"
val tokenizer = SimpleTokenizerV1(rawText)
val text = "Hello, do you like tea?"
val idList: List<Int> = tokenizer.encode(text)
println("idList.size: ${idList.size}")
println("idList: $idList")
println("Vokabular.size: ${tokenizer.vocabSize}")
----
Nicht überraschend, dass die idList 7 Elemente enthält. Auffallend aber, dass die ID 7 2x vorkommt.
[source, terminaloutput]
----
idList.size: 7
idList: [7, 1, 2, 3, 4, 7, 6]
Vokabular.size: 9
Vokabular: {Darling=0, ,=1, do=2, you=3, like=4, water=5, ?=6, <|unk|>=7, <|endoftext|>=8}
----

Die Vokabulargrösse ist 9, weil nach den über den rawText erstellten Tokens die beiden Konstanten
const val UNKNOWN = "<|unk|>"
const val ENDOFTEXT = "<|endoftext|>"
hinzugefügt werden.


Der zu enkodierende Text wird ebenfalls mit der tokenize() in Tokens aufgeteilt, welche dann im Vocabular gesucht werden und bei einem Treffer mit der zum im Vokabular zugehörigen ID zurück gegeben wird. Wird kein entsprechendes Token im Vokabular zurückgegeben wird die ID des UNKNOWN Tokens zurück gegeben. Die beiden Wörter Hello und tea aus dem Text sind im Vokabular nicht bekannt und dürften somit die ID des UNKNOWN Token erhalten. Naheliegend dass diese ID 7 sein könnte.
