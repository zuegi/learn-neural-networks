[[Tokenize]]
== Tokenize

Das LLM kann wie schon gesagt nichts mit Text anfangen. Deshalb braucht es einen Mechanismus den Text in einzelne Tokens aufzuteilen und diese Tokens in Zahlen zu wandeln und damit mathematische Operationen ermöglichen.
Ein Tokenzizer zerstückelt einen Text in kleine Bausteine, sogennante Tokens. Ein Token kann ein ganzes Wort, Teile eines Wortes oder eine Sequenz von Zeichen inklusive Satzzeichen darstellen. Jedem dieser Token wird eine Token-Id zugeteilt.


=== Konzept

Die Klasse SimpleTokenizerV1.kt ist ein einfacher regelbasierter Tokenizer, der aus rawText ein Vocabular mit stabilen numerischen IDs aufbaut.
Er erkennt Wörter mit Apostroph, typografischem Apostroph, Bindestrich und Unterstrich, einfache Satzzeichen sowie die Special Tokens "<|unk|>" und "<|endoftext|>".

Die Methode *encode* zerlegt neuen Text mit derselben Regex und mappt unbekannte Tokens auf die ID von UNKNOWN, statt sie zu verwerfen oder einen Fehler zu werfen.

Die Methode *decode* übersetzt IDs zurück in Tokens und setzt sie mit einfachen Leerzeichen- und Anführungszeichen-Regeln wieder zu Text zusammen.
Zusätzlich hält die Klasse ein Reverse-Mapping idToToken, stellt vocabSize bereit und ergänzt UNKNOWN sowie ENDOFTEXT immer am Ende des Vokabulars.

Leerzeichen selbst werden nicht als Tokens ausgegeben, weil nur gefundene Muster (it.value) gesammelt und als List<String> zurückgegeben werden.

Das Vocabular wird aus den tokens aufgebaut wobei jedes neue Token in Reihenfolge seines ersten Auftretens die nächste freie ID bekommt (`LinkedHashMap` hält Reihenfolge stabil).
Nach allen normalen Tokens fügt buildTokenToId immer zusätzlich UNKNOWN (<|unk|>) und ENDOFTEXT (<|endoftext|>) mit eigenen IDs an.
encode nutzt dieses Vokabular für Token→ID (unbekanntes Token fällt auf UNKNOWN zurück), und decode nutzt die inverse Map idToToken für ID→Token.
