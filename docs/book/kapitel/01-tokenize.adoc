[[Tokenize]]
== Tokenize

Ein Tokenizer ist ein Werkzeug oder Programm, das Rohtext (wie Sätze oder Wörter) in kleinere Einheiten, sogenannte Tokens (Wörter, Wortteile oder Zeichen), zerlegt und diese in Zahlenwerte umwandelt. Dieser Schritt ist notwendig, da KI-Modelle und Computer keine Buchstaben direkt lesen können, sondern nur mit Zahlen und Vektoren arbeiten.

=== Konzept

Zum Verständnis bauen wir einen einfachen, regelbasierten Tokenizer (mit einer Regex), der aus Rohtext ein Vokabular mit stabilen, numerischen IDs aufbaut.
Er erkennt Wörter mit Apostroph, typografischem Apostroph, Bindestrich und Unterstrich sowie einfache Satzzeichen und die Special Tokens „<|unk|>” und „<|endoftext|>”.

Die Methode *encode* zerlegt neuen Text mit derselben Regelbasis und mappt unbekannte Tokens auf die ID von UNKNOWN, anstatt sie zu verwerfen oder eine Fehlermeldung auszugeben.

Die Methode *decode* übersetzt IDs zurück in Tokens und setzt sie mithilfe einfacher Leerzeichen- und Anführungszeichen-Regeln wieder zu Text zusammen.
Zusätzlich hält die Klasse ein Reverse-Mapping idToToken bereit, stellt size bereit und ergänzt UNKNOWN sowie ENDOFTEXT immer am Ende des Vokabulars.

Die idToToken Map wird aus vocab abgeleitet:

* vocab.entries liefert alle Einträge des Vokabulars als Map.Entry<String, Int>
* { (token, id) -> ... } destrukturiert jeden Eintrag in token (Key) und id (Value)
* id to token erzeugt ein Pair<Int, String> – also genau umgekehrt zur ursprünglichen Zuordnung
associate { ... } baut daraus eine neue Map<Int, String>

Ergebnis: Aus {"the" -> 42, "cat" -> 17} wird {42 -> "the", 17 -> "cat"}.

*Zusammengefasst*: Für die Tokenisierung brauchen wir `vocab` (Text -> IDs), für die Eingabe des Modells).
Für die Detokenisierung bei der Textgenerierung braucht es die umgekehrte Richtung `idToToken` (IDs -> Text), um die vom Modell erzeugten Token-IDs wieder in lesbaren Text zurückzuwanden.



Somit sind wir nun in der Lage einen Text in Tokens bzw. Token-IDs aufzusplitten.
Die Funktion `encode` wandelt einen Eingabetext in eine Liste von Token-IDs um, indem sie zunächst mit derselben Regex tokenisiert, die auch beim Aufbau des Vokabulars verwendet wurde. Jedes so entstandene Token wird über die `vocab`-Map in seine ID übersetzt; ist ein Token unbekannt, wird stattdessen die zuvor ermittelte ID von `[UNKNOWN]` verwendet. Die ID von `[ENDOFTEXT]` erscheint dabei nur dann in der Ausgabe, wenn der Eingabetext das spezielle Token `<|endoftext|>` tatsächlich enthält – es wird also nicht künstlich ergänzt. Die Funktion bildet damit das Gegenstück zu `decode` und wird typischerweise verwendet, um rohen Text vor der Verarbeitung durch das Modell in die numerische Eingabeform zu bringen.

Die Funktion `decode` wandelt eine Liste von Token-IDs mithilfe der Reverse-Map `idToToken` zurück in ihre ursprünglichen Token-Strings und wirft dabei eine `IllegalStateException`, falls eine ID nicht im Vokabular vorhanden ist. Anschließend werden diese Tokens über `joinTokens` zu einem zusammenhängenden Text zusammengesetzt, wobei einfache Spacing-Regeln angewendet werden – etwa kein Leerzeichen vor Satzzeichen (`.`, `,`, `!`, `?`) oder vor Spezial-Tokens wie `[UNKNOWN]` und `[ENDOFTEXT]`. Zusätzlich gibt es eine vereinfachte Behandlung von Anführungszeichen, um den rekonstruierten Text natürlicher wirken zu lassen. Die Funktion bildet damit das Gegenstück zur Tokenisierung und wird typischerweise genutzt, um die vom Modell erzeugten Token-IDs während der Inferenz wieder in lesbaren Text umzuwandeln.

`joinTokens` fügt eine Liste von Tokens zu einem lesbaren Text zusammen, indem es anhand von zwei Regelmengen (`noSpaceBefore` für Satzzeichen/Sonder-Tokens, `noSpaceAfter` für öffnende Klammern) entscheidet, ob vor dem jeweils nächsten Token ein Leerzeichen eingefügt werden muss. Für Anführungszeichen wird zusätzlich der Zustand `quoteIsOpen` mitgeführt, um zu unterscheiden, ob ein `"` gerade ein öffnendes oder ein schließendes Anführungszeichen ist, und das Spacing entsprechend anzupassen (kein Space nach öffnendem, kein Space vor schließendem Quote). Das Ergebnis wird schrittweise in einem `StringBuilder` aufgebaut, wobei das erste Token ohne vorangehende Prüfung direkt übernommen wird.

So wird aus einem rawText "Darling, do you like water?" ein Vocabular aus Tokens und Token-IDs erstellt, welches dann über den text "Hello, do you like tea?" encoded wird.
Wie man unschwer erkennen kann unterscheidet sich der Text vom Vocabular in den 2 Wörtern Darling -> Hello, water -> tea.

Das Vocabular wurde über die obengenannte Regex in folgende 7 folgende Tokens aufgesplittet:

1. Darling
2. ,
3. do
4. you
5. like
6. tea
7. ?

[source, kotlin]
----
val rawText = "Darling, do you like water?"
val tokenizer = SimpleTokenizerV1(rawText)
val text = "Hello, do you like tea?"
val idList: List<Int> = tokenizer.encode(text)
println("idList.size: ${idList.size}")
println("idList: $idList")
println("Vokabular.size: ${tokenizer.vocabSize}")
----
Nicht überraschend, dass die idList 7 Elemente enthält. Auffallend aber, dass die ID 7 2x vorkommt.
[source, terminaloutput]
----
idList.size: 7
idList: [7, 1, 2, 3, 4, 7, 6]
Vokabular.size: 9
Vokabular: {Darling=0, ,=1, do=2, you=3, like=4, water=5, ?=6, <|unk|>=7, <|endoftext|>=8}
----

Die Vokabulargrösse ist 9, weil nach den über den rawText erstellten Tokens die beiden Konstanten
const val UNKNOWN = "<|unk|>"
const val ENDOFTEXT = "<|endoftext|>"
hinzugefügt werden.


Der zu enkodierende Text wird ebenfalls mit der tokenize() in Tokens aufgeteilt, welche dann im Vocabular gesucht werden und bei einem Treffer mit der zum im Vokabular zugehörigen ID zurück gegeben wird. Wird kein entsprechendes Token im Vokabular zurückgegeben wird die ID des UNKNOWN Tokens zurück gegeben. Die beiden Wörter Hello und tea aus dem Text sind im Vokabular nicht bekannt und dürften somit die ID des UNKNOWN Token erhalten. Naheliegend dass diese ID 7 sein könnte.
